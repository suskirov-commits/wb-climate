# wb-climate — климат-контроль на Wiren Board

Пользователь задаёт в помещении температуру, система сама управляет всей
инженерией помещения как одним целым. Работает на штатном движке правил
[wb-rules](https://github.com/wirenboard/wb-rules). Настраивается через
веб-интерфейс контроллера, без правки кода.

**Что есть сейчас:**

* конвекторы: простые (только термоголовка) и активные — термоголовка
  и вентилятор: 1–3 скорости на реле, плавно 0-10 В (WB-MAO4), Modbus
  (регистр скорости конвектора со своим контроллером);
* тёплый пол: петли коллектора на термоголовках, регулирование по
  датчикам пола в границах «не ниже / не выше»;
* пол и конвекторы в одном помещении работают в связке: пол несёт
  основную нагрузку, конвекторы догревают.

**Дальше:** фанкойлы 2/4-трубные, кондиционеры, вентиляция, увлажнение —
от той же уставки и той же потребности помещения. Порядок работ, статус
и чек-лист первой проверки на объекте — [ROADMAP.md](ROADMAP.md).

## 1. Как это работает

```
 датчики помещения ─► ЗОНА (помещение) ─► потребность в тепле 0…100 % ─┬─► тёплый пол    (0–70 %)
 уставка, окно           регулятор П+И                                  ├─► конвектор 1   (50–100 %)
                                                                        └─► конвектор 2   (50–100 %)
```

**Зона** — одно помещение и одно виртуальное устройство. Она сравнивает
температуру с уставкой и считает **потребность в тепле**:

* чем больше разница, тем больше потребность. При отставании на «зону
  пропорциональности» (по умолчанию 1,5 К) — 100 %;
* медленная интегральная часть копит «сколько тепла помещению нужно
  вообще». Без неё в мороз температура держалась бы с недобором: при
  нулевой разнице чистый П-регулятор даёт ноль, а тепло нужно. На стенде
  при −20 °C чистый П недогревает на 0,6–0,9 К.

**Конвектор** раскладывает потребность на свои выходы:

| Потребность | Термоголовка | Вентилятор |
|---|---|---|
| 0 % — уставка достигнута | закрыта | стоит |
| больше 0 % | открыта | стоит: греет естественная конвекция |
| от 20 % | открыта | 1-я скорость (0-10 В — минимальная) |
| растёт | открыта | скорость растёт |
| 100 % — большое отставание | открыта | максимальная скорость |

Чем ближе температура к уставке, тем медленнее вентилятор; он
останавливается раньше, чем закрывается термоголовка. Термоголовка
закрывается, когда уставка достигнута.

**Тёплый пол** регулируется по своим датчикам в стяжке (один или
несколько — среднее). Потребность помещения превращается в **целевую
температуру пола**, термоголовки петель держат её:

| Потребность помещения | Цель для пола |
|---|---|
| 0 % — помещению тепло | «Пол не ниже» (minFloor): петли закрыты, пол остывает, но не ниже — тогда петли открываются |
| растёт | растёт |
| 100 % — помещению холодно | «Пол не выше» (maxFloor, 29 °C) — выше никогда |

* **«Пол не ниже» держится всегда**: и при выключенном помещении, и при
  открытом окне. Сильнее него только «Пол не выше». Выключить пол совсем
  (летом) — «Пол не ниже» = 0. Хозяин правит его на карточке помещения,
  значение из настроек — начальное;
* «Пол не ниже» = «Пол не выше» — пол просто держит заданную
  температуру, уставка помещения на него не влияет;
* «Пол не ниже» = 0 — низ цели равен уставке помещения: пол, равный по
  температуре воздуху, тепла не отдаёт;
* «комфортный пол» греет и тогда, когда помещению тепло не нужно, —
  помещение может перегреться (на стенде при +8 °C на улице минимум
  25 °C перегревает комнату на 1 °C);
* нет датчиков пола или все отказали — петли работают ШИМ по
  потребности помещения (цикл 20 мин), на карточке предупреждение;
  держать минимум не по чему;
* **без смесительного узла** (в петли идёт вода от котла 45–60 °C) схема
  работает — на стенде точность воздуха ±0,2 К вместо ±0,09. Но датчик
  в гильзе между трубами не видит перегрева пола над трубами: «Пол не
  выше» ставить по покрытию (паркет, ламинат — 27 °C).

**Пол и конвектор в одном помещении.** У каждого прибора своя доля общей
потребности — «Участие в нагреве»:

| Роль | Доля потребности |
|---|---|
| Авто (по умолчанию) | есть и пол, и конвекторы — пол «Основной», конвекторы «Догрев»; иначе «Всегда» |
| Основной | 0–70 % |
| Догрев | 50–100 % |
| Всегда | 0–100 % |
| Свои границы | «Потребность от» … «до» |

Без деления конвектор забирает больше половины работы: на стенде при
−20 °C пол давал только 43 % тепла, вентилятор переключался 4 раза в час.
С делением 0–70 / 50–100 пол даёт 87–95 % тепла, точность ±0,08 К,
утренний выход с ночных 20 °C — 31 мин (у одного пола — 3,5 часа).

**Защита от холодного дутья.** Термоголовке нужно 2–4 минуты, чтобы
открыться, и ещё время, чтобы теплообменник прогрелся. Вентилятор ждёт
3 минуты после открытия термоголовки или, если задан датчик воды,
пока вода не прогреется до 30 °C.

**Реле скоростей.** Одновременно включено только одно реле: два отвода
обмотки, замкнутые даже на миг, — это межвитковое замыкание. При смене
скорости старое реле выключается, новое включается через 0,5 с. Между
сменами ступеней выдерживается минута, при снижении скорости работает
гистерезис. Без этого шум датчика щёлкал бы реле на каждом такте.

**Защиты и режимы зоны:**

* несколько датчиков температуры — берётся среднее по исправным; отказ
  части датчиков — авария на карточке, работа продолжается; отказ всех —
  авария и безопасная потребность (по умолчанию 0: не греть);
* выбросы с шины (обрыв 1-Wire отдаёт 85 °C) отбраковываются;
* открытое окно (дольше 30 с) — отопление на паузе, клапаны закрыты
  сразу; тёплый пол держит только «Пол не ниже»;
* защита от замерзания (7 °C) работает и в выключенном помещении;
* потеря связи с модулем реле или аналогового выхода — авария; выход,
  который модуль сбросил после перезапуска, восстанавливается;
* проверка конфигурации до запуска: пустые обязательные поля или одно
  реле в двух местах — помещение не запускается, на карточке
  «Ошибка настройки» и что исправить;
* сохранение сценария в веб-интерфейсе не сбрасывает выходы: открытый
  прогретый конвектор продолжает дуть.

## 2. Установка

### Способ 1 — пакет (основной, с формой настроек)

Установка и обновление — одна команда на контроллере:

```sh
U=https://github.com/suskirov-commits/wb-climate/releases/latest/download
wget -O /tmp/wbclim.deb $U/wb-climate_all.deb && dpkg -i --force-confold /tmp/wbclim.deb
```

`--force-confold` оставляет конфигурацию объекта при обновлении.

### Способ 2 — один файл через веб-интерфейс

`dist/wb-climate.js` → веб-интерфейс → **Правила** → новый скрипт →
вставить → в секции `CONFIG` вписать свои топики → сохранить. Страницы
настроек в этом варианте нет. Пакет и однофайловую сборку одновременно
не ставить — помещения задвоятся.

### Способ 3 — на тестовый контроллер по ssh

```sh
make deploy HOST=192.168.1.50
```

Конфигурация копируется, только если её на контроллере ещё нет.

## 3. Настройка на объекте

1. **Настройки → Климат-контроль.** Для каждого помещения:
   * **Температура** — один или несколько датчиков (WB-MSW, WB-MS, 1-Wire);
   * **Отопительные приборы** — «Добавить», выбрать «Конвектор» или
     «Тёплый пол»:
     * конвектор — реле термоголовки; тип вентилятора и его выходы.
       Реле скоростей — от медленной к быстрой;
     * тёплый пол — реле термоголовок петель, датчики пола,
       «Пол не ниже» / «Пол не выше»;
     * id и название прибора можно не заполнять — присвоятся сами,
       следующим номером после занятых: conv2, «Конвектор 2». То же
       для помещений: climate_room2, «Помещение 2»;
   * при наличии: датчик окна, датчик воды конвектора.
2. **Сохранить.** На карточке помещения (**Устройства**) должно быть
   состояние «Нагрев» / «Уставка достигнута», а не «Ошибка настройки».
3. **Проверка проводки:** **Режим → Ручная потребность (проверка)**.
   * «Ручная потребность» 100 % → щёлкает реле термоголовки; через
     3 минуты включается максимальная скорость;
   * 60 % → вторая, 30 % → первая (для трёх скоростей);
   * 0 % → всё выключено.

   Проверить на месте, что скорости совпадают с реальными.
   В помещении с полом и конвекторами ручная потребность делится
   так же, как в авто: конвектор включается с 50 %.
   **Вернуть режим «Авто».**
4. **Уставка** — на карточке, шаг 0,1 °C.

### Карточка помещения

| Контрол | Что это |
|---|---|
| Включено, Режим, Уставка | управление |
| Температура, Влажность | средние по исправным датчикам |
| Окно открыто | если задан датчик окна |
| Потребность в тепле | что регулятор требует от конвекторов, % |
| Интегральная часть | «постоянная» часть потребности, % |
| Ручная потребность | для проверки (режим «Ручная потребность») |
| *Конвектор*: клапан / вентилятор / вода / состояние | по каждому конвектору |
| *Тёплый пол*: петли / пол / цель для пола / пол не ниже / состояние | по каждому полу; «пол не ниже» правится здесь |
| Состояние, Авария, Описание аварии | |
| Зона пропорциональности, Время интегрирования | настройка регулятора на месте |
| Сброс аварии | |

### Если что-то не так

| Наблюдение | Что сделать |
|---|---|
| Температура колеблется больше ±0,3 К, реле скоростей щёлкают часто | увеличить «Зону пропорциональности» до 2 К |
| Долго выходит на уставку, вентилятор подолгу на средней скорости | уменьшить «Зону пропорциональности» до 1 К |
| В мороз держит стабильно на 0,3–0,5 К ниже уставки | уменьшить «Время интегрирования» (30 → 20 мин) |
| После солнца/гостей перегрев долго не уходит | увеличить «Время интегрирования» (30 → 45 мин) |
| Вентилятор включается, а дует холодным | увеличить «Задержку вентилятора» или поставить датчик воды |
| Пол долго «гуляет» вокруг цели | «Гистерезис пола» 0,5 → 1 К |
| «id … повторяется» в описании аварии | очистить поле id у второго прибора (помещения) — номер присвоится сам |
| В помещении с полом конвектор работает постоянно | пол не тянет нагрузку: проверить подачу в пол или поставить конвектору «Свои границы» с 60 % |

### Модули Wiren Board

* **WB-MR6C** (реле термоголовок и скоростей): безопасное состояние —
  **выключено**, при включении питания — **безопасное состояние**.
  Обесточенная NC-термоголовка закрыта, вентилятор стоит.
* **WB-MAO4** (0-10 В вентилятора): выход в милливольтах 0…10000.
  Для вентиляторов 2-10 В «Значение при 0 %» = 2000.

### Конвекторы со своим контроллером (Modbus)

Конвектор подключается к Wiren Board как Modbus-устройство (Настройки →
Конфигурация устройств), его регистры появляются как контролы. В форме
климат-контроля: термоголовка — контрол клапана платы, вентилятор —
«Modbus», выход — контрол скорости.

* **Ступени** (`steps` 3): пишется номер ступени 0…3. Если регистр ждёт
  проценты — «Значения ступеней», например 30, 60, 100.
* **Плавно** (`steps` 0): шкала `valueMin`…`valueMax`. Плата может
  сохранять каждую запись в энергонезависимую память, поэтому изменения
  меньше `minChange` (5 %) не пишутся. Пуск, остановка и 100 % — всегда.
  На стенде: 4 записи в час вместо 87 при той же точности.

Шаблон устройства Varmann Vartronic для wb-mqtt-serial — следующим шагом.

## 4. Параметры

Все поля — в форме настроек, с подсказками. Пример с комментариями —
[etc/wb-climate.conf.example](etc/wb-climate.conf.example).

**Помещение**

| Поле | По умолчанию | |
|---|---|---|
| `control.band` | 1,5 К | зона пропорциональности |
| `control.ti` | 30 мин | время интегрирования, 0 — чистый П |
| `control.period` | 10 с | такт |
| `safety.frostTemp` | 7 °C | защита от замерзания |
| `safety.failSafeDemand` | 0 % | потребность при отказе всех датчиков |
| `window.delay` | 30 с | проветривание короче — не в счёт |

**Конвектор: термоголовка**

| Поле | По умолчанию | |
|---|---|---|
| `normallyOpen` | нет | NC: обесточена — закрыта |
| `mode` | `onoff` | `onoff` — по потребности; `pwm` — ШИМ |
| `minOn` / `minOff` | 120 / 120 с | минимальное время открытой / закрытой |
| `openTime` | 180 с | время полного открытия |
| `cycle` | 900 с | период ШИМ |

**Конвектор: вентилятор**

| Поле | По умолчанию | |
|---|---|---|
| `start` | 20 % | потребность, с которой включается |
| `hyst` | 10 % | гистерезис снижения скорости |
| `minStepTime` | 60 с | выдержка между сменами скорости |
| `delay` | 180 с | ждать прогрева теплообменника |
| `minWater` | 30 °C | то же по датчику воды |
| `interlock` | 500 мс | пауза при смене скорости (реле) |
| `min` / `max` | 20 / 100 % | диапазон плавной скорости (0-10 В, Modbus) |
| `steps` | 3 | Modbus: ступеней, 0 — плавно |
| `values` | — | Modbus: значения регистра для ступеней 1..N |
| `minChange` | 5 % | Modbus плавно: не писать изменения меньше |

**Тёплый пол**

| Поле | По умолчанию | |
|---|---|---|
| `floorSensors` | — | датчики в стяжке, среднее по исправным |
| `minFloor` | 0 (по уставке помещения) | пол не ниже, °C; держится всегда; начальное — дальше на карточке |
| `maxFloor` | 29 °C | пол не выше: EN 1264 — 29 жилые, 33 санузлы; СП 60.13330 — 26 |
| `floorHyst` | 0,5 К | гистерезис по полу |
| `valve.cycle` | 1200 с | ШИМ, если датчиков пола нет |
| `valve.minOn` / `minOff` | 180 / 180 с | минимальное время открытых / закрытых петель |

**Любой прибор**

| Поле | По умолчанию | |
|---|---|---|
| `role` | `auto` | `auto`, `base` (0–70 %), `boost` (50–100 %), `all`, `custom` |
| `demandFrom` / `demandTo` | 0 / 100 | границы для `custom` |

## 5. Почему такие умолчания

Параметры подобраны на стенде [test/sim.js](test/sim.js): помещение
(воздух + ограждения), термоголовка с реальным запаздыванием, теплообменник
конвектора, вентилятор по ступеням, датчик с инерцией и шумом. Прогон:
установившийся режим при −20 °C, +400 Вт теплопоступлений, окно на 10 мин,
ночное снижение до 20 °C и утренний возврат к 22 °C.

| Вариант | Размах, К | Утро 20→21,7 °C | Смен скорости в час |
|---|---|---|---|
| **по умолчанию: 1,5 К, 30 мин** | ±0,16 | **19 мин** | 8 |
| 2 К, 60 мин | ±0,13 | 83 мин | 9 |
| чистый П | ±0,15, но **недобор 0,6 К** | не выходит | 7 |

Умолчания проверены ещё на четырёх помещениях: лёгкое, конвектор
вдвое мощнее и слабее нужного, подача 45 °C.

Тёплый пол — модель стяжки 60 мм на 20 м² (постоянная времени ~2 ч),
подача 35 °C:

| Вариант (−20 °C) | Размах, К | Утро 20→21,7 °C | Доля тепла от пола |
|---|---|---|---|
| только пол, по датчику пола | ±0,09 | 215 мин | 100 % |
| **пол + конвектор, 0–70 / 50–100** | **±0,08** | **31 мин** | **87 %** |
| пол + конвектор без деления | ±0,21 | 19 мин | 43 % |

```sh
node test/sim.js                       # таблица вариантов
node test/sim.js --trace --ti=0        # трасса раз в 5 минут
```

## 6. Разработка

```
etc/wb-rules-modules/wbclim-util.js       датчики, фильтры, группа датчиков
etc/wb-rules-modules/wbclim-valve.js      термоголовка: onoff / ШИМ, NC / NO
etc/wb-rules-modules/wbclim-fan.js        вентилятор: реле, 0-10 В, Modbus
etc/wb-rules-modules/wbclim-convector.js  конвектор: клапан + вентилятор
etc/wb-rules-modules/wbclim-floor.js      тёплый пол: каскад по датчикам пола
etc/wb-rules-modules/wbclim-zone.js       помещение: регулятор, защиты, устройство
etc/wb-rules/wb-climate.js                точка входа
etc/wb-climate.conf                       эталон (пустые топики)
etc/wb-climate.conf.example               пример с комментариями
usr/share/wb-mqtt-confed/schemas/…json    форма настроек (генерируется)
tools/make-schema.js                      генератор формы настроек
dist/wb-climate.js                        однофайловая сборка (генерируется)
test/harness.js                           эмулятор рантайма wb-rules
test/zone.js, bundle.js, schema.js        автотесты (312 проверок)
test/sim.js                               стенд: модель помещения
```

```sh
npm install          # ajv, acorn — только для тестов
make test            # или: node test/zone.js && node test/bundle.js && node test/schema.js
make build           # после правки модулей — иначе bundle.js упадёт
node tools/make-schema.js   # после правки формы — иначе schema.js упадёт
```

Код — только ECMAScript 5 (duktape в wb-rules): `test/bundle.js`
проверяет каждый файл.
